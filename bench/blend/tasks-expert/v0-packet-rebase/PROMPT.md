# Rebase v0 static indices while keeping packet size, stale signatures and message domains consistent

Repair the existing modules; `index.ts` exports `solve(input)` returning JSON. The wrapper returns `{error:"invalid"}` for exceptions. All rules below are authoritative, including when starter code/comments disagree. Public examples are deliberately incomplete.

Input {message,signatures,permutation,blockhash,newData,limit}. The message wire is standard v0 MESSAGE bytes: 0x80, three u8 header fields required/readonlySigned/readonlyUnsigned, canonical short-u16 static count,32-byte keys,32-byte blockhash, short-u16 instruction count; each instruction is u8 static program index,short-u16 account-index count,u8 indices,short-u16 data length,data. Then short-u16 lookup count; each lookup is table key32,short-u16 writable count,u8 indices,short-u16 readonly count,u8 indices. short-u16 is minimal 7-bit continuation, at most3 bytes, max65535. Static keys unique,1..256; required1..255 <=static count, readonlySigned<required, readonlyUnsigned<=static-required. Combined static+loaded<=256; accounts index combined space, program indices STATIC ONLY. Each lookup's writable+readonly index lists must be disjoint with no repeats; descriptor order and index order otherwise preserved. Reject suffixes/truncations/unsupported versions. No message packet cap unless specified. signatures array has exactly required entries {key,signature}, one per original STATIC signer key in any order; signature is null or opaque64-byte hex (not cryptographically verified here). No unknown or duplicate signer keys. permutation is a bijection listing OLD static indices in NEW order, payer index0 fixed; each old index must remain within its original one of four header role partitions. blockhash is the replacement key. newData<=32 {instruction numeric index,data hex<=65535}, unique indices, permits identical replacement. Remap static program/account indices via inverse permutation; loaded indices are unchanged. If ANY serialized message byte changes, ALL nonnull signatures become null, not just signatures whose signer moved; preexisting nulls are not listed stale. Reorder signer entries to new static signer order. Build canonical TRANSACTION as short-u16(required)+64-byte signatures (null encoded all zeros)+new raw message. limit numeric64..65535 applies to FINAL transaction only. Output {message,packet,size,signatures,stale,digest}; stale lists NEW signer positions of invalidated nonnull signatures ascending; digest=SHA256(new RAW MESSAGE only), size must equal exact packet byte length and independent size calculator.
