# Apply atomic Token-2022 withholding, harvest and withdrawal

Repair the existing implementation of `solve(input)` in this small offline Node 22 package. Preserve the API; edit the implementation modules, not tests. No packages, network, RPC, filesystem or clock are needed. Several modules contain interacting defects. The intended fix is compact; do not replace the package with a large framework.

Input {epoch,schedule,mintWithheld,accounts,ops}. accounts are {id,balance,withheld,frozen}; IDs are unique strings; frozen is boolean. Ops: {kind:"transfer",from,to,amount,expectedFee}, {kind:"harvest",ids}, {kind:"withdraw",to,authority}. Transfers require distinct existing unfrozen accounts, sufficient source balance, and exact expectedFee under the schedule; source loses gross, destination gains gross-fee and destination withheld gains fee. Harvest zeros listed accounts' withheld balances and adds them to mintWithheld, including frozen accounts; reject repeated/unknown IDs. Withdraw requires authority===true and an unfrozen existing destination, moves ALL mintWithheld into its balance and zeros the mint. Every intermediate stored amount must fit u64. Apply atomically: on ANY operation error return {committed:false,accounts:original,mintWithheld:original,fees:[]}; otherwise return {committed:true,accounts,mintWithheld,fees}, with per-transfer fees in operation order. Invalid initial state or malformed op shape returns invalid, not an uncommitted result. Empty batches are legal. Extra fields may be ignored.

All byte strings are canonical lowercase even-length hex. Unsigned token/lamport amounts are canonical decimal strings in [0, 2^64-1]. Indices/epochs are nonnegative safe integers unless a narrower bound is stated. Reject malformed/out-of-range inputs with exactly `{error:"invalid"}`; never mutate input, even on failure. Successful BigInt values are returned as decimal strings by the existing entrypoint. Do not silently coerce numeric strings or repair malformed wire data.

Run `node --test visible.test.ts`. Hidden tests also cover coupled invariants and boundaries; passing the public examples alone is not the contract.
