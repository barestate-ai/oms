# Migrate Borsh extension directories into canonical permission bitmaps

Repair the existing implementation of `solve(input)` in this small offline Node 22 package. Preserve the API; edit the implementation modules, not tests. No packages, network, RPC, filesystem or clock are needed. Several modules contain interacting defects. The intended fix is compact; do not replace the package with a large framework.

Input {data}; prefix SHA256("account:Registry")[:8], version u8 1/2, owner[32], record count u16<=64. V1 record {tag u8,len u16,payload}; V2 {tag u16,len u32,payload}; exact complete consumption, duplicate tag rejected, tags>0. Mandatory tag1 limit is u64 in V1/u128 in V2. Mandatory tag2 name is a strict UTF8 Borsh string <=128 bytes, BOM preserved. Optional tag3 roles: V1 u32 count<=64 then {key[32],permissions u8} (bits 0=read,1=write,2=admin, no others); repeated V1 keys UNION permissions. V2 u16 count<=64 then strictly lexicographically increasing unique keys then THREE bitmaps (read/write/admin), ceil(count/8) bytes each, LSB-first; unused tail bits must be zero. Unknown tags/payloads preserved byte-exact. Always output sorted-by-tag V2 records, always including roles tag3 even if absent, with sorted role keys and lossless limit. Return {data,limit,name,roles:[{key,permissions}],unknownTags:[sorted numbers]}. Role permission zero is legal and preserved. No payload >65535 bytes. Reject migration if adding the mandatory roles record would exceed 64 total records.

All byte strings are canonical lowercase even-length hex. Unsigned token/lamport amounts are canonical decimal strings in [0, 2^64-1]. Indices/epochs are nonnegative safe integers unless a narrower bound is stated. Reject malformed/out-of-range inputs with exactly `{error:"invalid"}`; never mutate input, even on failure. Successful BigInt values are returned as decimal strings by the existing entrypoint. Do not silently coerce numeric strings or repair malformed wire data.
